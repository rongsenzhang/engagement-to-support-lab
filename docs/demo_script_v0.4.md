# Five-minute v0.4 demonstration

This is an AI-assisted independent prototype, not a Kortext product. The script
describes executed historical analysis and prepared synthetic study software;
there are no real participant findings or recordings yet.

## 0:00–0:45 — Research question

Show **Research question**.

“This project asks how learning traces can support a careful human review. The
original experiment compares models at the same workload: 637 of 6,362 historical
module enrolments. Adding trend and assessment context to activity increased the
number of later withdrawals in that list from 121 to 162. That does not mean 41
withdrawals were prevented. The reference rule is also my explicit specification,
not Kortext's proprietary algorithm.”

## 0:45–1:45 — A useful negative result

Show **Course robustness → Within-course results**, then **Module EEE**.

“A pooled result can conceal differences between courses. B and C both contain
activity and trend, so B-to-C isolates the added assessment features. That
comparison improves ranking in three courses and worsens it in two. Here, the
top-10% list contains 21 later withdrawals with B and only nine with C. This
course has no eligible assessment due at day 28. That is an applicability state,
not a missing feed. I retained the negative result and investigated its meaning.”

## 1:45–2:30 — Transfer and model complexity

Show **Held-out courses**, macro summary, then **Outer module GGG**.

“I tested transfer by holding out whole courses in the development data, keeping
students apart and separating selection from calibration and evaluation. A
controlled nonlinear model has better average precision across the five courses,
but worse probability error than C and does not win every course. On this course
B remains stronger. These are exploratory historical findings, so I have not
automatically replaced the original default.”

## 2:30–3:15 — Data availability changes interpretation

Show **Simulated delays → Submission events from days 26–28 delayed**.

“Withholding 60 submission records replaces 54 positions in C's 637-record list.
The population and actual outcomes have not changed. The case view shows the
same learner evidence before and after the simulated delay. A changed score
therefore cannot be treated as proof that learning changed; someone needs to
check the source record and deadline context.”

## 3:15–4:30 — Prepare to test user understanding

Show **Tutor practice**. Begin Practice; briefly show the pattern pair and the
missing-submission task. Do not claim this rehearsal is a user study.

“The next question is whether a tutor can understand those limits. This separate
module uses 50 invented cases, with four tasks: compare patterns, reconsider an
initial judgement after new context, choose five records to review, and explain
an uncertain prediction. Initial judgements are saved before context is disclosed.
The participant's own revision remains separate. A manual capacity limit is not
an instruction to allocate real support.”

## 4:30–5:00 — What is ready and what remains

“The system, participant information, facilitator guide, observation template
and private summary tool are ready. I will arrange three to five relevant adult
volunteers later. Practice records are excluded from participant counts; no
feedback or design improvement based on users has been invented. The next
evidence needed is actual understanding and workflow feedback, followed by
appropriate contemporary validation before considering a live pilot.”

If asked about implementation, explain the protocol, the B/C comparison, why
course priors and student isolation matter, one failure case, and the limits of
historical evaluation. State the role of AI assistance accurately and use genuine
professional experience for claims about qualifications or stakeholder work.
